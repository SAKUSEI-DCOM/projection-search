# Projection デビュー情報（非公式）

GitHub Pages向け静的サイトです。掲載対象はデビュー予定・デビュー済みの両方です。

## 公開手順
1. GitHubで公開用リポジトリを作り、このフォルダ内の全ファイル（`.github`を含む）をアップロードします。
2. リポジトリの **Settings → Pages → Build and deployment → Deploy from a branch** を選択し、`main` / `(root)` を指定します。
3. 公開URLは通常 `https://ユーザー名.github.io/リポジトリ名/` です。反映に数分かかることがあります。

## ライバー情報の登録・修正
公開ページの「管理・データ更新」で編集し「JSONを書き出す」を押し、生成された `livers.json` をGitHubリポジトリ直下の同名ファイルと置き換えてコミットしてください。ブラウザ内で保存しただけでは公開データは変わりません。GitHub Pagesにログイン式管理画面はありません。編集権限はGitHubのリポジトリ権限で管理します。

JSONの項目：`id`, `name`, `debut`（`YYYY-MM-DDTHH:MM`、日本時間）, `image`, `x`, `iriam`, `source`, `memo`。公開済みの情報と利用許可済みの立ち絵だけ登録してください。初配信日時が不明なら空欄にします。

## 自動収集（候補の抽出）
`data/sources.json` に**利用条件を確認した公開RSS/Atomフィード**を登録します。例：

```json
[
  {"name":"許可された公式お知らせフィード", "feed_url":"https://example.org/feed.xml"}
]
```

GitHub Actionsが約6時間ごとに記事を確認し、`初配信`・`デビュー`・`初枠`・`立ち絵公開` 等を含む記事のURLと見出しを `candidates.json` に保存します。ActionsはGitHub側のスケジュールにより遅延する場合があります。GitHubの **Actions → Check public announcements → Run workflow** から手動実行もできます。

**重要**：候補は未検証です。名前、配信時刻、立ち絵は自動推定・自動掲載しません。候補を公式発表と照合し、サイトの編集フォームから `livers.json` に反映します。SNSの無許可スクレイピングは実装していません。Xの投稿を直接自動収集する場合は利用規約に沿う公式API等の接続設定が別途必要です。現在の `sources.json` は空なので、初期状態では新規候補は収集されません。

## 注意
非公式サイトです。IRIAM/Projectionとは無関係です。GitHub Pagesは静的ホスティングのため、サイト上での管理操作はGitHubのファイルに直接書き込めません。公開画像の権利と転載許可を確認してください。

## 7日間の配信予定カレンダー（追加）

- 閲覧日を起点に **日本時間（JST）の今日から7日間** を表示。初配信は `livers.json` の初配信日時からも自動表示されます。
- デビュー済みライバーの通常配信・企画配信は `schedules.json` で管理。各項目には `name`, `start` (例 `2026-11-12T20:00`), `type` (`stream`, `debut`, `special`), `title`, `source`（告知元URL）, `link`（IRIAM URL）, `status` (`confirmed`, `tentative`, `cancelled`) を設定します。`end` は任意。
- HTMLの管理欄から配信予定を編集して `schedules.json` を書き出し、GitHubのリポジトリ直下にアップロードしてください。ブラウザのローカル保存は全員に公開されません。
- `data/x_accounts.json` の `handles` に、**公開投稿を収集してよい所属ライバーのXアカウント**を登録します。初期値は公式 `Projection_VL` のみです。実際の所属アカウントは確認してから追加してください。
- GitHub Settings → Secrets and variables → Actions → New repository secret に `X_BEARER_TOKEN` を設定すると、GitHub ActionsがX API v2の recent search で公開投稿候補を取得します。**XのAPIプランや権限によって検索APIが利用できない場合があります**。APIキーなしではXの自動収集は動作しません。`data/sources.json` に利用許可のあるRSS/Atomを登録した場合はそちらも収集できます。
- 収集候補は `candidates.json` に保存されます。日時の解釈（「明日」「今夜」など）、画像告知、延期・中止の判断は人手で確認して `schedules.json` に反映します。X投稿をそのまま自動確定する仕組みではありません。
- 投稿本文の再配布や立ち絵画像の無断転載を避け、出典リンクと許可された画像のみ掲載してください。APIの利用規約・料金を事前に確認してください。
- GitHub Actions の `schedule` は実行時刻が遅れることがあります。自動収集は約6時間ごとで、リアルタイムではありません。

## v3 無料自動化の実態と設定
- `data/sources.json` に**配信者または公式が公開した、利用可能なRSS/AtomのHTTPS URL**を `[{"name":"情報源名","feed_url":"https://..."}]` の形式で登録。初期状態は空なので自動取得はゼロです。
- GitHub Actionsは6時間ごとにWiki照合・公開フィード収集・明示日時の抽出を実施。年/月/日と時刻、ライバーの一意照合ができるものだけを暫定予定として追加します。イベントも出典付きで登録します。
- X公式APIの無償枠は保証されません。Xの非公式スクレイピングやログイン回避は実装していません。Xだけに掲載された告知は、正規に利用できる公開フィード等がなければ自動取得できません。
- 管理者が手動修正したデータは上書きせず、収集情報には `auto_imported` と `verification` を付けます。日時の変更・中止は自動確定できないため告知元で再確認してください。
- 公開GitHubリポジトリで Actions を有効にし、Workflow permissions を Read and write に設定。GitHub Pagesを main/root で公開。スケジュール実行は遅延・停止する場合があります。


## v4: 3時間ごとの自動巡回

`.github/workflows/collect.yml` のスケジュールを `17 */3 * * *` (UTC) に変更しました。日本時間では毎日 **02:17 / 05:17 / 08:17 / 11:17 / 14:17 / 17:17 / 20:17 / 23:17** を予定します。GitHub側の都合で遅延・スキップする場合があります。`Actions` から手動実行もできます。

実行内容：Wiki照合 → プロフィール補完 → 設定済みRSS/Atom・任意の公式X APIの候補収集 → 確度を限定した予定追加 → `data/health.json` の状態更新 → 差分があれば自動コミット。処理の重複実行を防ぐため `concurrency` を設定しています。

**重要**：`data/sources.json` は初期状態では空です。X APIを利用しない場合、Xの投稿を直接取得する機能はありません。外部RSS/Atomが存在し利用条件を満たす場合のみ登録してください。Xのスクレイピング・非公式ミラーを使って無料監視できると保証するものではありません。自動抽出は暫定情報として表示し、実際の配信中判定は行いません。

GitHub上の既存ファイルと統合するときは、登録済みの `livers.json`、`schedules.json`、`special_events.json` をバックアップしてください。初回のGitHub Actions実行後、`data/health.json` で情報源数とエラーを確認できます。
